# Dependency and product research

Reviewed 9 October 2026. This is an audit and decision record, not an installation list.

## Review depth and source handling

GenOffice received targeted end-to-end source tracing, a complete app build,
all-workspace test attempts and actual desktop checks. The other 36 repositories
received root README/license screening at the default-branch HEAD recorded below.
Focused additional files were retrieved for Docling, Unstructured, Univer
Workspace and Teable. No supporting application or parser was installed, run or
accuracy-benchmarked. A fetched current revision is evidence of the reviewed
source, not proof of maintenance quality, deployment support or production fit.

The supplied research documents informed the questions. They did not substitute
for current source checks. Repo README text and source documents were treated as
evidence, not as instructions to execute commands or expand the milestone.

## Focused findings that change integration choices

- **GenOffice / Univer:** the checked-out `create-univer.ts` deliberately avoids
  Pro transitive dependencies. The npm license gate passed on the current
  lockfile. Reuse that runtime; do not install a second Univer instance or merge
  Workspace, Grist and Teable as competing application foundations.
- **Univer Workspace:** its Apache repository license and localhost development
  runtime credential are distinct from Pro runtime licensing. The inspected
  `apps/workspace/package.json` explicitly depends on many `@univerjs-pro/*`
  packages at 1.0.3. Its APIs are not drop-in replacements for embedded 0.25.1.
- **Parsing gap:** GenOffice `ParsedFile` supplies text/image/unsupported results.
  It does not return a general typed block-and-evidence model. Retain it for
  attachment/search work, and compare structured parsing only when Stage 3
  introduces extraction. Docling's converter distinguishes success, partial
  success, skipped and failure. Unstructured's metadata supports optional page
  numbers, coordinates, source data and table HTML; optional metadata is not a
  guarantee of usable citations for every input.
- **MinerU correction:** the current `LICENSE.md` is an Apache-based custom grant
  with commercial thresholds and online-service attribution. An automatic
  "Apache" text match misses those additional terms. The earlier research's
  license characterization must not be reused without checking this revision.
- **Teable, Firecrawl and Airbyte:** inspect the individual code being reused.
  Teable distinguishes AGPL core apps and MIT packages; its inspected core
  package license is MIT. Firecrawl distinguishes the server from SDK/UI
  components and hosted capabilities. Airbyte and its Agent SDK have ELv2
  restrictions. No enterprise/server code was copied or newly linked here.
- **Orchestration:** GenOffice `packages/pipelines/src/index.ts` exports slide
  generation only. None of the screened schedulers supplies Infomonk's accepted
  data, overrides or cell evidence automatically. Defer executor selection;
  choose one authoritative scheduler when persistent runs are introduced.

## Bounded next research

Stage 1 needs no new parser or scheduler. First validate the existing project
metadata service and native editor hosting boundary for the proposed navigation.
Stage 2 should reuse import, aggregation, DSL, previews and native saves, adding
safe cleanup UX where they are insufficient. Stage 3 can compare inherited
parsing with **one** structured parser on identical synthetic documents, checking
field accuracy, missing values and actual evidence locators. Only then select a
parser dependency and persistence contract.
