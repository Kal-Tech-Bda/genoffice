# Infomonk application test — 10 October 2026

The built Windows desktop app passed **39 native journey checkpoints** and
**16 Electron regression tests**. Testing found and fixed two workflow UI bugs.
The complete Shell and Sheets suites still contain **21 known Windows failures**;
this is not an all-green suite result.

Tested local commit `b8c9f3d5` plus the ResearchPanel fix and regression tests in
this working tree. [Machine-readable results](app-test-2026-10-10/results.json)
record the full commit, source hashes, checkpoint names, live retrieval evidence
and environment. Earlier milestone verification records remain historical.

## Fixes verified

| Trigger                                                    | Before                                                                              | Verified behavior                                                                                                               |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Inspect an accepted cell, then save a separate workflow    | The previous workflow's evidence inspector and correction controls remained visible | Saving clears the cell inspector, accepted view and review choices, and selects the new workflow's schedule                     |
| Inspect accepted data, then retry cancelled durable inputs | The new candidate remained hidden behind the accepted table                         | Retry exposes the candidate, clears stale evidence and resets issue/removal review choices; accepted revision remains unchanged |

Both new tests failed against the original built app and passed after rebuilding.
The permanent regression cases are in
[`e2e/infomonk-research-context.spec.ts`](../../e2e/infomonk-research-context.spec.ts).
The fix changes renderer review state; database schema, extraction and provider
contracts are unchanged.

The desktop journeys exercised project create/import, rename/star/search,
TSV cleanup with preview/discard/apply, record origins, sorting guards, formulas,
undo/redo, native save, byte-equivalent XLSX export, fresh-process reopen and
previous-version restore. DOCX/PDF source previews, tab/section preservation,
Assistant drafts, collapse/resize and light/dark themes ran in actual Electron
WebContentsViews.

Research journeys covered PDF/DOCX/text extraction, related line items,
duplicate business keys, missing facts, exact source inspection, transactional
publication, corrections, idempotent refresh and persistent paused schedules.
Live World Bank retrieval produced 18 population observations across six countries
and three years using two pages; enrichment preserved internal/manual/external
origins. HTTP denial, pending cancellation and interruption were **injected test
fixtures**, separately recorded from live public retrieval. Accepted data survived
failures, retry and restart. Refresh reviewed added/changed/absent records and
retained a manual correction. The actual app-open scheduling timer queued one due
run, stopped at review and preserved the accepted revision; only the isolated
database's due timestamp was advanced.

Additional checks verified DOCX label/value and line-item table extraction with
exact cell locators, owned source snapshots after original-file mutation, blocked
publication after partial failed acquisition, and rejection of an empty copied
workflow. Native sheet edits preserved embedded evidence and displayed the
difference from accepted values after restart.

The 16 permanent Electron cases also cover CSV in-place save/export and formula
loss prompts, TSV opening, filter save/reopen, Find & Replace, empty DOCX/XLSX/PPTX
save, Assistant side/layout/draft persistence and theme restart.

## Remaining failures and verification limits

The failures match the documented prior Windows results:

- Shell: one Linux desktop-ID basename assertion; two symlink privilege/environment
  cases; 16 headless-export cases using POSIX absolute-path fixtures.
- Sheets: two atomic-file promotion tests use directory `chmod` to simulate write
  denial, which does not create the expected Windows permission failure.

The affected test files remain unchanged from the supplied upstream revision.
These failures are recorded in the [results](app-test-2026-10-10/results.json) and
local raw logs, rather than hidden or treated as passing. See the
[baseline verification](../audit/verification.md) for the earlier broader audit.

No model/provider/account/cloud requests were tested. Windows x64 is the tested
platform; installers and other operating systems remain unverified. Document
inputs are synthetic. This verifies the supported quote and bounded World Bank
workflows, not arbitrary documents, OCR or generic website collection.
