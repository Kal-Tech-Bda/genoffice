# Infomonk: accepted outputs and returning-user review

The workspace now distinguishes sharing accepted facts from sharing an editable
workbook. Outputs exports any displayed accepted revision directly, using the
existing XLSX projection and writer. Publication, preview recovery and failed
refreshes make their state explicit. The owner's order remains **UI/UX review,
then the engineering harness next**; generated execution is still disabled.

This pass builds on the [earlier UI review](ui-ux-2026-10-12.md),
[persona iteration](../use-cases/persona-iteration-2026-10-12.md) and
[Bermuda coverage use case](../use-cases/bermuda-coverage-2026-10-12.md).
It does not claim a new live job search or complete market coverage.

## What changed and why

- **Outputs:** counts accepted revisions; has distinct loading, failed and empty
  states; clears results immediately when leaving a project. Each revision offers
  Export accepted data and Open editable workbook; current revisions also offer
  Inspect accepted table. Late reads and export outcomes cannot appear in a
  different project. Clicking Outputs again retries a failed read.
- **Accurate sharing:** accepted export reconstructs all tables from that exact
  SQLite revision, including tracking, notes and evidence metadata. Filters do
  not narrow the export; source snapshot bytes remain in the workspace. Editor
  Export workbook remains a copy of the saved editable file. Both export paths
  reject managed data, registered project files, original sources and aliases;
  existing hard-linked destinations are rejected conservatively.
- **Returning later:** Home names the last working workbook and its filename,
  including an explicitly opened older revision. A failed HTML refresh opens the
  accepted table and explains retrying its durable capture versus fetching fresh
  bytes. Accepted HTML source, table and key identities are read-only during
  configuration edits; name/notes remain editable after a source update.
- **Publication:** review acknowledgement enables Publish. Success remains
  explicit even if the accepted preview response fails; Reload accepted preview
  restores it without another publication. Keyboard focus returns to the table
  or success message. Filters continue working after publication.

## UI gate completion evidence

The generated personas cover starting a project, acquiring whole tables, reviewing
and maintaining data, tracking a shortlist, sharing a result and returning later.
Existing complete-table acquisition and ledger queries avoid manual row copying
and reach rows beyond the first displayed page without model calls. Accepted
sharing now starts in Outputs and requires no detour through an editable workbook.
No token-cost or general-browser performance benchmark is claimed.

The earlier UI pass plus this regression provides executed evidence for simpler
starts/configuration, readable source scope, keyboard evidence inspection,
tracking/focus, honest refresh failures, revision-specific sharing, reopening,
narrow geometry and both themes. These improvements complete the current persona
iteration and make the UI reviewable before harness implementation. Templates,
rich reports, broader discovery, localization and deployment remain later work.

Remaining boundaries: HTML acquisition supports complete static tables and may
reject a page with active next/load-more controls even when unrelated to a table;
native cell edits still need reviewed corrections to survive research refresh;
exports include personal tracking/notes and evidence, but not source snapshots.
Destination validation and writing are separate operations, so concurrent
filesystem replacement remains a timing limitation. No new framework, provider
call, application, notification subscription or generated-code runner was added.
