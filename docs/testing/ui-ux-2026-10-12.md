# UI/UX gate before the engineering harness

The owner's 12 October order is **UI/UX first, harness next**. This pass improves
existing workspace interactions and reuses the accepted ledger, editors and
acquisition routes. It adds no framework, dependency, provider request or generated
execution. The older harness-last wording in current roadmap documents is superseded.

## Changes and observed behavior

| Flow              | Friction addressed                                                   | Result                                                                                                             |
| ----------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Source checks     | Long URLs squeezed scope text into very tall rows                    | Compact names/hosts and explicit scope badges; exact text, URL, timestamp and evidence remain expandable           |
| Job views         | Six filters and no applied-state feedback occupied the screen        | Primary search/role/source controls, expandable secondary filters, active presets and unapplied-change feedback    |
| Cell inspection   | A click appeared to do nothing because details were below all tables | Selection reveals and focuses the panel; readable labels and expandable technical metadata; Close restores context |
| Personal tracking | Saving while a filter removed the row could lose keyboard focus      | Restore after the table commits and controls re-enable; table-heading fallback for a removed row                   |
| Workflow review   | Long pages made it hard to return to the dataset or publish section  | Explicit Go to table and Review and publish navigation                                                             |
| Narrow navigation | The full sidebar and long action labels squeezed main panels         | Compact named controls below 1,000px; wrapping source/output/project rows; Settings and Help stay reachable        |
| Project creation  | A new or failed file could leave the previous sample visible         | Clear/announce pending reads, ignore obsolete responses, block pending/failed submission and retry the same file   |
| Dialog keyboard   | Focus could leave the modal or be lost after dismissal               | Tab/Shift+Tab containment, Escape dismissal, focus restoration and development StrictMode setup/cleanup support    |
| HTML table setup  | Missing sources and mixed confirmation were unclear                  | Source guidance, loading/readiness announcements, mixed header state, keyboard discovery and named preview headers |

Source coverage stays conservative: partial checks are labeled partial; missing
matching counts read **Not checked**, not zero. Scope and source evidence remain
unchanged. Configured publisher names in compact job rows are identified as such.
Employer facts remain read-only; personal status and notes remain separate.

## Verification

Final commands and results are recorded in [results.json](ui-ux-2026-10-12/results.json).
Across the selected runs, **17 unique native journeys pass**; two explicit live
network acquisition cases remain skipped for this UI pass. Shell build/typecheck,
theme, English-comment and license checks pass. Lint has zero errors and 12 existing
warnings. Corrected regression assertions now distinguish an empty-state row from
data rows and use stable navigation names while checking visible source counts.
Focused native checks exercise actual service/parser/IPC code; synthetic fixtures
and delayed responses are identified in their records. The saved live tracker
test leaves its accepted revision unchanged and sends no application or tracking
write. Separate synthetic tracking tests exercise actual accepted updates.

Windows 10.0.26200; Node v24.13.1; Electron 43.7.6; Playwright 1.62.1. The build
uses the committed npm dependency graph. Native tests launch `apps/shell/out` with
isolated `GENOFFICE_USER_DATA` profiles via `e2e/helpers.ts`.

## Remaining limits and next milestone

This is a bounded UI review, not a formal accessibility certification or a timed
human usability study. Wide research tables still scroll horizontally at narrow
sizes. Source search covers the loaded coverage page, while job filters cover the
full ledger. Technical proof remains available on demand. Provider-dependent
research execution remains untested without credentials; inherited Assistant
layout can be checked without a model request.

The next milestone is the engineering harness, following this UI/UX gate. Use
existing provider/tool transport, durable attempts and reviewed ledger contracts.
The first bounded invoice pattern and isolation requirements remain in
[Stage 6 preparation](../implementation/stage-6-preparation.md). Broader input
families, templates, deployment and localization do not block beginning that work.
