# Infomonk readiness review before Stage 6

Historical findings: the subsequent [hardening milestone](hardening-2026-10-10.md)
addresses the six items below. Original measurements remain preserved here.

Reviewed 10 October 2026 against the supplied build prompt, the local Stages 1–5
implementation and the latest desktop test record. `assay.md` remains excluded.
This review adds evidence and planning records; it makes no new application changes.

**A short hardening milestone is warranted before expanding the agent.** The
small supported journeys work, but history scaling and portable restoration have
confirmed gaps. There is also a mismatch between input and evidence size limits,
and one outstanding Stage 5 reuse journey.

## Exact source connections

- History: [`ResearchStore.run/runs`](../../apps/shell/src/main/research/store.ts)
  parses candidates, overlays corrections, reads accepted datasets and recomputes
  diffs for every history record. `ResearchService.state` returns those records.
  [`ResearchPanel`](../../apps/shell/src/renderer/src/infomonk/ResearchPanel.tsx)
  requests them every 1,500 ms, independently of whether a candidate is selected.
- Evidence capacity: [`projectDataset`](../../apps/shell/src/main/research/projection.ts)
  embeds the dataset in `infomonk/research.json`.
  [`ResearchService.sheetCell`](../../apps/shell/src/main/research/service.ts)
  rejects that part above 16 Mi characters. The input schema permits 20 documents,
  and extraction permits 1,000 items per document. Separate bounds do not establish
  a compatible end-to-end capacity.
- Restore: [`WorkspaceStore`](../../apps/shell/src/main/workspace-store.ts)
  stores absolute primary/previous workbook and owned snapshot paths. Research
  workflows, revision destinations and durable inputs also retain absolute paths.
  Original source URIs may correctly remain external; owned restored paths must
  resolve inside the restored workspace.
- Reuse: the `copy` handler in
  [`research/ipc.ts`](../../apps/shell/src/main/research/ipc.ts) saves into the same
  project and clears source IDs, countries and parent references.
  [`ProjectCreator`](../../apps/shell/src/renderer/src/infomonk/ProjectCreator.tsx)
  offers file/question/link starts, without a workflow-template start.
- Agent boundary: [`codex-app-server.ts`](../../packages/ai-provider/src/codex-app-server.ts)
  supplies a restrictive model-only instruction and permission profile, with a
  read-only fallback. That fallback is not private-data isolation. Preserve this
  bridge's existing role while building a separately enforced runner boundary.

## Executed evidence

All diagnostics used synthetic local data and isolated `.task` profiles. No
provider requests, new frameworks, upgrades or changes to user profiles were made.

The history experiment populated legitimate storage shapes directly to isolate
read cost. It does not certify extraction accuracy or a production capacity.
Three source-level samples were taken at each history size; the native check used
three sequential calls through the built shell, preload and main IPC. Native
timings exclude the diagnostic's final JSON-length calculation.

| ---- | ------------------- | ---------------- | --------------------------- | ------------------------------------------------------------- |
| 1    | 1,000               | 1.51 MiB         | 27.68 ms                    | Not measured                                                  |
| 10   | 1,000               | 15.12 MiB        | 266.35 ms                   | Not measured                                                  |
| 50   | 1,000               | 75.61 MiB        | 1,369.82 ms                 | Not measured                                                  |
| 100  | 1,000               | 151.21 MiB       | 2,715.07 ms                 | Median 40,373.5 ms; samples 40,129.7 / 40,449.5 / 40,373.5 ms |

XLSX projection took 21.29 ms for 100 items and 498.89 ms for 1,000 items in the
source-level probe. No full 20,000-item XLSX build/publication was attempted.

The restore test copied a closed synthetic profile to a new location and launched
the built desktop with that new `INFOMONK_USER_DATA`. The original remained intact.
Accepted data survived, but owned and evidence paths were not relocated. Failure
when the original is removed is an inference from those retained references;
the original was not deleted or moved to manufacture a failing test.

## Scope and decisions for the next milestone

Close history payload/polling, compatible evidence limits and portable recovery
before increasing data volume or autonomous processing. Complete or explicitly
defer cross-project template creation. Checkpoint the tested implementation.

At the start of Stage 6, define the first supported new pattern, acceptance corpus,
provider data policy, isolation method, filesystem/network scope, time/memory/output
and cost budgets. Generated-code execution must remain unavailable if actual
isolation is unavailable. Publication checks remain outside agent control.
Use existing agent/provider, editor and ledger seams instead of creating another
assistant loop or scheduler.

The following are known later-roadmap work, rather than forgotten requirements
for this local checkpoint: OCR/difficult layouts, more connectors, stronger entity
resolution, hosted/background execution, teams, automatic retention, linked
document outputs, localization, installer/signing and non-Windows release checks.
The 21 known Windows unit-test failures and live provider verification remain
release/compatibility work. The PDF candidate-parser comparison is incomplete
because its optional dependency was unavailable; revisit it only when broader
input coverage calls for that comparison.
