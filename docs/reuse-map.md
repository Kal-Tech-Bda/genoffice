# GenOffice capability and reuse map

Baseline reviewed 9 October 2026 at `1ca5e9adfc1807a158db19741eff825dba9ab757`.

**Conclusion:** retain the desktop shell, live editors, embedded Univer, workbook
engines, file search, native save paths, shared UI, provider configuration and
agent loop. Infomonk needs a project-oriented product layer and a maintained-data
domain, not new office editors or a second spreadsheet engine.

Evidence labels:

- **Runtime:** exercised in the actual Electron application on Windows.
- **Tests:** applicable automated checks ran; consult the verification record
  for failures/skips. A passing package does not verify every file format.
- **Source:** followed the implementation; not demonstrated end to end.
- **Unavailable:** live path needs configuration or environmental support.
- **Deferred:** proposed Infomonk behavior, absent from the audit deliverable.

Source paths below are relative to the repository root. Where a directory is
listed, the adjacent entrypoint identifies the inspected path. Detailed results
and screenshots are in [audit/verification.md](audit/verification.md).

## New capabilities, ranked by when they are needed

1. **Stage 1 — local project product model and hosting chrome.** Expose existing
   metadata primitives through a focused gateway; add description, star and primary
   workbook association. Build project navigation around live WebContentsViews.
2. **Stage 2 — safe cleanup journey.** Reuse import, range reads, aggregation,
   planning, commands and saves; add header/delimiter confirmation, chosen keys,
   preview/discard and source-preserving transformations with formula/load guards.
3. **Stage 3 — source snapshots, evidence and accepted storage.** New stable record
   identities, source/version locators, candidates, missing reasons, reviews and
   human corrections; compare one structured parser against inherited helpers.
4. **Stages 4–5 — acquisition and repeatable execution.** Bounded web adapter,
   identity matching, versioned workflow/run state, diff publication and one
   scheduler matched to the actual deployment.
5. **Stage 6 onward — isolated engineering and linked outputs.** Focused agent
   tools, enforceable quality gates and execution isolation; editable templates and
   secondary outputs derived from accepted versions.

No new capability in that list was implemented in this audit. The hosted fork
is established and connected as `origin`; branding, extraction, live provider
calls, source refresh, schedules and team authorization remain deferred or
unverified as recorded above.
